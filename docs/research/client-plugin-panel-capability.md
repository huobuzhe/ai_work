1. **（信息，非决定）不推翻第二轮 Q1(a)，但把其中「客户端插件(面板)」从假设升级为一手坐实的事实，并补出两条此前没写的约束。** 一手证据显示 `ctx.sidebarRightTabs.register({…, keepMounted: true })` + `ctx.slots.register("sidebar.right.pane.tab", Body)` 提供跨刷新/跨 session 保留的常驻右栏面板，且外部包走与内置类型相同的公开路径（`ui-sidebar-documentpreview` 是官方举的活证），已安装的 `dsh-univer-office` 更用 `priority: "extension"` 实打实注册了一个带 iframe 表格视图、按钮与输入/配置 dock 的右栏 tab；`ctx.layout.selectPanel` / `shell.bottom` 还提供全局面板与底栏。因此 Q1(a) 的后半段无需改。需要补的是：(a) 这是 **Web surface（`platform: "web"`）的面板，不是独立窗口/新页面**；(b) 活证里的表格视图是**同源 iframe Viewer**（`/univer-viewer` 路由 + `connection.requestRejection` 鉴权），不是插件 React body 内嵌的可编辑 grid（未验证 #4）—— 若 Q1(a) 隐含「面板里直接编辑表格」，该具体形态仍需单独定。

2. **（信息，非决定）对 /to-spec 测试 seam 的影响：最高 seam 应落在 client-plugin 包内、且落在「不依赖 HMR 后仍存活的 React state」的契约上。** ⑤ 的一手文档逐字写明 reload 是 coarse（「React state inside the reloaded plugin is lost」）、「No failure rollback」、「Web transport only」，且 bundle 内容只经 `rebuilt()` 进 graph。因此任何断言「面板常驻状态跨热更存活」的测试都不可靠；更稳的 seam 是 (i) 插件侧 `dsh.client` 声明 / `sidebarRightTabs.register` 的注册契约，(ii) 把状态投影到 Host 侧权威源（活证用的 `FileState`「始终是 worktree 当前状态与 Viewer URL 的权威来源」、`Session` 对象 / `dsh.sidebar-right.v1.<sessionId>` 布局 JSON），(iii) Viewer URL / 同源路由的 HTTP 契约。/to-spec 倾向「越少 seam 越好、尽量复用既有 seam」——这里既有 seam 就是 `ctx.sidebarRightTabs` + `ctx.slots` + Viewer 路由，不需要新造。

3. **（信息，非决定）交付形态应是「一个带 `dsh.client` 的插件包」，而不是改 apps/web shell 或普通 packages。** ② 给出包骨架（`package.json` 声明 `dsh.client` / `platform: "web"` / `./client` 导出 + `build:client` 脚本 + `cordis.patch.yml`），本机 `dsh-univer-office` / `dsh-better-sidebar` / `dsh-pocket` / `dsh-pet` / `dsh-prompt-enhancer` 都是可照抄的一手范例。这一点若走反（改 shell），⑤ 判定 2 明确要求「重建 Web artifacts + 刷新页面」，会直接抬高验收成本；走插件包则开发期可在 HMR 下迭代。另注意 ⑤ 的 `dsh-web-app` 逐字说明「The apps/web Vite entry builds the shell but is not a standalone application because only dsh web injects window.__DSH_BOOT__」—— 交付物不能是「一个能独立打开的 Vite 应用」。

4. **（信息，非决定）验收/发布路径与开发期路径必须分开写进验收条件。** 开发期：client-plugin 改动可免刷新热更，但前提是**有 rebuild watcher 在跑**（`pnpm run dev:web` 同时起 host + watcher；`--no-serve` 或共享 Client tsdown preset 的 watch 进程可接别处宿主；`cordis.patch.yml` 逐字 "idle until a rebuild watcher … actually rewrites client bundles"）—— 即「receiver active」≠「热更一定发生」，必须「verify that watcher before promising automatic updates」。发布/验收：shell 与 packages 改动须重建 Web artifacts 并刷新页面验证既有 URL；且「Starting another server does not update this GUI」「Do not start a replacement server unless the user asks」。建议把「watcher 是否在跑」作为 /to-spec 里一条明确的前置检查，而不是隐含假设。
